# Retainer Pricer

Dalamud API 15 plugin for pricing items in the retainer sale window.

## Use

1. Open the plugin with `/retainerpricer` or the short alias `/retainer`, from the main menu, while viewing a retainer's selling list, or from the optional server info bar shortcut when enabled in Settings.
2. Automatic new-item pricing and both batch actions use Universalis. A price is suggested from current competing listings of the same quality; no recent sale is required. With no competitors, existing prices stay unchanged; new listings use the same-quality 30-day sales median, applying the selected pricing rule and minimum. Without usable recent sales either, new listings are skipped.
3. Open a retainer's sale list and click **Start listing items**. It processes all eligible carried inventory automatically: skips bound, untradeable, nonmarketable, excluded, saved gear-set, or inactive items; checks Universalis; prices each item with your selected pricing rule; and confirms each new sale. Each sale is capped at 99 items; larger stacks continue in follow-up listings. Items configured on the **Batch selling** tab are split into smaller listings; other items stay as full stacks up to that cap. Current competitors take priority. Without competitors, new listings use the matching-quality 30-day sales median; without either source, they are skipped. If **Exceptions** is empty, a confirmation offers **Proceed**, **Stop**, or **Proceed and don't show again**; only the last choice is remembered. It stops when eligible inventory is done, the retainer's 20 slots are full, or you press **Stop**. If it cannot verify that a sale reached the retainer list, it stops before trying another item.
4. In **Batch selling**, use **Add current inventory** to add eligible carried items in one step, or add items individually. Set a maximum quantity per listing and an optional maximum total for that item in a **Start batch selling only** run. No sale exceeds 99 items; larger quantities continue in another listing if space remains. For example, a batch size of 5 and total limit of 20 lists at most 20 items in four listings; 0 means no total limit. **Start listing items** still processes all eligible inventory, using the per-listing size. **Start batch selling only** processes only configured items; all other carried inventory is ignored. Exclusions take priority, and listing stops at the normal 20-slot limit. If Exceptions is empty, a confirmation appears before either listing start action.
5. To check a price without listing, use **Price lookup** and retrieve from Search or a captured inventory or retainer-list row. The result appears below Search and on the **Retrieved price** subtab, with cheapest and home-world listing prices, recent purchase prices, world names, and data ages for your selected HQ/NQ quality. The suggested price using your selected pricing rule remains below. When **Automatically price and confirm new listings** is enabled, opening an eligible new sale window checks Universalis, submits the listed price, and verifies it in the retainer list. Use **Start listing items** to process all eligible carried inventory in one run.
6. To automatically reprice all retainers, click **Auto update** from the retainer picker to go top-to-bottom, or open any retainer's selling list to process that retainer first. It then visits each other available retainer once. Inactive retainers are skipped. Auto update advances the selected retainer's greeting dialogue, retrying while the Talk box remains open, then opens its options menu. It uses your price scope and exclusions, verifies every changed listing, shows the current retainer and item, and displays an approximate ETA after the first retainer finishes; the estimate updates as the run progresses. It stops if the character, world, or selected retainer changes unexpectedly. **Stop** prevents further submissions; already submitted changes remain applied. This currently requires the game UI language to show the standard English retainer menu labels.
7. To reprice only the active retainer, click **Update existing listings**. It checks each eligible listing against Universalis, applies your selected pricing rule, submits the update, and verifies it before moving to the next item. A proposed drop beyond the configured percentage is held while the rest of the retainer is processed, then asks **Approve this price** or **Ignore**. In the **Existing listings** tab, set separate thresholds for listings under 10,000 gil (default 50%), 10,000–999,999 gil (25%), 1,000,000–9,999,999 gil (10%), and 10,000,000 gil or more (5%). Auto update uses the same thresholds and pauses at the same review for each retainer. Approval triggers a fresh quote before applying; rows show whether a price was applied or skipped for missing recent history or competition. Use **Exclude** to add an item to the persistent exception list. Changing character, world, or active retainer stops an update.
8. Use **Don't reprice** to block price changes to selected existing listings through **Update existing listings**, **Auto update**, and current-item price controls. Refresh carried inventory to fill its item picker, or search the full item list. Read-only price lookup still works, and the item remains eligible for new listings from inventory. In **Exceptions**, refresh carried inventory or the chocobo saddlebag to find items, add one selected item, or bulk-add either snapshot. Exceptions are item-based and apply when the item is later in carried inventory or selected for Retainer sell. Items assigned to a saved gear set are automatically protected from automatic listing, repricing, and Retainer sell; removing them from Exceptions does not override this protection.
9. In **Sniper**, choose the lookback window (0–14 days; 0 ignores sale age), deal threshold, minimum sales, and minimum listing value, then click **Start watching**. The configurable threshold defaults to **91.0%** of the median. Ordinary deals below the minimum per-item value are hidden; new 1-gil listings always bypass this filter and remain highlighted once per item, world, and quality. Sniper's independent **Market scope** selector uses your home world by default, the full Data Center, or the home-world region only (Materia/Oceania is included only if it is your home region). All marketable items is the default; use the Sniper item search and picker before Start watching to scan and watch one specific item instead (both HQ and NQ). It scans the selected items in Universalis history batches of up to 100 item IDs, with up to two concurrent batches sharing the plugin-wide 25-requests-per-second and eight-connection limits while monitoring live listings. New 1-gil alerts appear immediately; other new listings can appear as their history batch finishes. In Region scope, server names include their Data Center, such as **Alpha (Light)**. An ETA appears during this initial scan only; background listening does not repeat the full scan. Click the **Server** column header to group deals by server; click **Listing** to sort prices ascending or descending. A listing becomes a deal when its unit price meets the minimum value, is at or below the chosen percentage of its same-quality median sale price, and that quality has at least the configured number of sales in the chosen window. The API returns up to 500 recent sales per item for this all-item scan. Later updates refresh an existing 1-gil alert instead of adding duplicate rows. Alerts are informational; purchases remain manual. Use **Stop watching** to cancel the scan or disconnect the feed.
10. In **Retainer sell**, summon a retainer and open **Sell items in your inventory**, set the maximum market price (default **1 gil**), and click **Start retainer sales**. By default, the plugin checks marketable carried items with Universalis and sells a whole stack through **Have Retainer Sell Items** only when its lowest matching HQ/NQ listing is at or below your threshold. Refresh carried inventory in this tab to select items for the **Retainer sale whitelist**, or search the full item list. Whitelisted items bypass marketability and price checks and send them straight to the retainer sale action. Other items still need a complete matching market price, and the plugin skips your own retainer listings. Bound items can be sold only when whitelisted; Exceptions and saved gear-set items remain protected. The game decides whether each whitelisted item is sellable. Sales use the game's NPC base gil value, not a marketboard listing price. The plugin verifies each inventory change before continuing. Sales cannot be undone, so review the whitelist and exclusions first; use **Stop** to halt further sales.
11. In **Universalis lookup**, open the retainer picker or any retainer's selling list and click **Refresh all retainer listings**. The plugin advances each retainer's greeting and farewell dialogue automatically, then saves a separate snapshot for each retainer and queues item IDs whose listings were added, changed, or removed. The snapshots and queue persist between sessions; refreshing again reconciles that retainer's snapshot, removes IDs no longer listed by any retainer, and searches each remaining item ID only once. Click **Look up listed items on Marketboard** to process the queue. If no marketboard is open, the plugin asks you to open one, then automatically searches each queued item and opens its listings. Completed results leave the queue; items not reached remain queued if you stop or a request fails. Universalis contribution depends on XIVLauncher marketboard reporting being enabled; Retainer Pricer itself does not upload market data.

Prices compare HQ and NQ separately, exclude all of your retainers, and follow the pricing rule selected in **Settings**: match the lowest usable competing listing or price one gil below it. Existing-listing repricing uses configurable price-drop review bands based on the current listing price: 50% below 10,000 gil, 25% from 10,000 to 999,999 gil, 10% from 1,000,000 to 9,999,999 gil, and 5% at 10,000,000 gil or more by default. Change the percentages in the **Existing listings** tab; Update existing listings and Auto update share them. A proposal beyond its band is held for a user decision after the rest of that retainer's scan. Approving fetches a fresh quote; ignoring leaves the listing unchanged. Your choice is remembered for that item across the current run, including Auto update's other retainers, and is cleared when the run ends so the next run asks again. Inventory snapshots read the four carried inventory bags; bound gear (detected from spiritbond), untradeable items, and items without a marketboard search category are skipped automatically. The optional maximum-age filter is off by default. Use the **Exceptions** tab to grab carried inventory, filter item names, select an item from the dropdown, and add or remove persistent exclusions. The **Don't reprice** tab uses the same carried-inventory and chocobo saddlebag picker for its protected-list entries. The picker hides items already excluded; use **Add current inventory** to exclude all marketable items in your carried inventory at once. The separate **Don't reprice** tab blocks plugin price changes to selected existing listings through automated repricing and current-item controls; read-only lookups still work, and those items remain eligible for new listings. Excluded items remain visible in the list with a **Remove** button, while manual price lookups remain available. On-screen price checks and automatic batches use Universalis. Automated runs stop if the character disconnects, begins loading or logging out, changes character or world, or the active retainer/item/menu transition cannot be verified; an item without a usable price is skipped. If **Start batch selling only** is clicked before adding any items to the **Batch selling** tab, the plugin shows “Batch selling list is empty.”

**Venture cycle:** At a summoning bell, open the retainer picker, enable **Run ventures** in the **Ventures** tab, and click **Start venture cycle**. Retainer jobs are detected automatically; use the per-retainer job dropdown only if you need to override detection. Each retainer defaults to Quick Exploration. Other venture choices are generated automatically from each retainer's job and level; miner, botanist, and fisher choices are limited to items recorded in your Gathering Log. No venture item menu needs to be opened. Use **Refresh available ventures** after unlocking new gathering items; the Gathering Log check also refreshes automatically while the tab is open. Choose whether idle retainers receive their selected venture and whether completed ventures are repeated. The cycle uses Retainer Pricer's game UI controls and does not require AutoRetainer; Auto update remains a separate action. Stop leaves the current game window open.

Successful Universalis responses are cached in memory for 5 minutes by default, keyed by market scope and item. Change the cache window or turn it off in **Settings**; the optional price-upload age filter remains independent. The **Pricing rule** selector chooses whether suggestions match the lowest eligible listing or undercut it by 1 gil. The **Pricing** selector in **Settings** offers three choices: **World** (the default, using your home-world listings), **Data Center** (all worlds on your home-world Data Center), or **Region** (all Data Centers in your home-world region plus Materia/Oceania). This scope applies to automatic pricing and manual lookups; local marketboard checks stay on your home world. Sniper's market scope is configured separately on the **Sniper** tab. The **On-screen price check source** selector offers Universalis. Per-item batch sizes affect new listings only; the batch-only total cap limits how much of that item is listed during one batch-only run. Existing listings are repriced without changing their quantities. The plugin version appears at the bottom-left of the menu.

Universalis requests for pricing are on demand and limited to the selected item and configured market scope. Sniper loads the chosen 0–14-day history window (0 ignores age) for every marketable item in batches of up to 100 IDs, running up to two history batches concurrently within shared request limits. While those batches run, it monitors live listings across the same scope. New 1-gil alerts show immediately; ordinary new listings appear as their item's history batch finishes. In Region scope, each server name includes its Data Center. Temporary history request failures are retried once, and persistent failures are shown in Sniper status. Sniper keeps watching the same scope after the initial scan. Up to 500 recent sales per item are used to calculate separate HQ/NQ medians; highly traded items can have additional older sales omitted by that per-item limit. New 1-gil listings are always flagged even when they are below the configured minimum listing value. Alerts never buy items. Retainer sell uses the shared price scope from Settings and checks each eligible carried stack before invoking the retainer's NPC-value sale action. The plugin itself does not upload player or market data; Universalis lookup relies on the separate XIVLauncher marketboard data reporter, when enabled.

## Install

In Dalamud Settings → Experimental → Custom Plugin Repositories, add `https://raw.githubusercontent.com/Jacob5800/DalamudPlugins/main/repo.json` for installer updates.

### Don't vendor

The **Don't vendor** list at the bottom of **Retainer sell** blocks NPC sales of selected items (HQ and NQ), even when whitelisted. It does not exclude items from **Start listing items** or batch marketboard listings. Use the search/picker and Add/Remove controls as with the other lists.

Retainer sell's whitelist and Don't vendor lists can be expanded or collapsed using their headers, which show saved item counts. Collapsing a list does not disable it. The green Start retainer sales button remains outside these sections.


Auto update completes the price pass first, then starts the venture cycle if **Run ventures** is enabled, using your current venture settings. Stopped or failed pricing runs do not start ventures. Auto update is orange.


**Update existing listings** reprices all retainers, with no venture cycle. **Auto update** reprices all retainers and then runs ventures when enabled. Both can start from the retainer picker or an open selling list.


The green **Update listings current retainer only** button below Existing listings updates only the open retainer and does not start ventures.


Saved retainer snapshots include **Time left in venture**; refresh snapshots to capture current venture completion times. The countdown is based on the saved completion time. **Which venture** includes an item-name search field: leave it empty to browse all available choices.


The Ventures table expands with the window and has resizable columns, with extra width for Which Venture.


## Inventory list shortcuts and undercut notifications

Inventory right-click menus provide separate Add/Remove entries for Exceptions, Don't reprice, Batch selling, Retainer sale whitelist, and Don't vendor. Disable all five using Settings → Show inventory right-click list options (enabled by default). Entries apply to both HQ and NQ. Batch entries start at 10 per listing with no total limit; edit their quantities in Batch selling. Existing Exceptions and saved gear-set protections still take priority.

Undercut notifier compares saved retainer listing prices with home-world Universalis listings of the same quality every 60 seconds while watching. Refresh all retainer listings first and after sales or repricing. Snapshot and market-data timestamps are shown; this is cached market information, not a guarantee that an undercut remains available. Unknown owners and saved own-retainer IDs are ignored. Echo alerts can be turned off and repeat alerts for the same retainer/item/quality/saved-price are suppressed for the plugin session. Pause and hide in duties / instances is enabled by default. It never changes prices.

Pricing rules include Match lowest, Undercut by 1 gil, Custom gil amount (1–10,000), and Percentage (1–100%). An amount input appears beside the dropdown only for the custom rules. Percentage prices round down to whole gil; reductions cannot produce less than 1 gil. Prices below the configured minimum are skipped, and existing price-drop review bands still apply. Inventory Add menu labels are green for market lists and yellow for Retainer sale whitelist / Don't vendor. Remove labels are always red.

Inventory Add options are filtered per action: market options require a tradable, searchable, unbound, non-collectible item; vendor options require an NPC sell value. Exceptions can protect either category. Batch, repricing, and sale-whitelist additions also respect existing Exceptions and saved gear sets; Don't vendor takes priority over the sale whitelist. Saved entries always retain their Remove option even if the current stack is ineligible.

Open the plugin with /retainerpricer, /retainer, or /rp. If another plugin already owns /rp, the original commands remain available.

Sniper watching in World scope automatically runs Undercut notifier checks. Stopping Sniper stops linked checks, unless independent notifier watching is enabled. Starting the notifier independently never starts Sniper. Data Center and Region Sniper runs are not linked; the notifier always compares home-world listings.

Start listing items and Start batch selling only save the active retainer's full listing snapshot after each confirmed listing, reusing the existing confirmation read without additional market requests. Undercut notifier uses this saved stock; listing runs do not start watching. Other retainers still require their own snapshot refresh.

A yellow Start venture cycle shortcut sits beside Start batch selling only at the top. The existing button in Ventures remains available. Both use the same venture settings and require Run ventures to be enabled.

Percentage undercut accepts up to two decimal places within 1–100%, for example 5.2%. Existing whole-number settings are preserved. The resulting asking price rounds down to whole gil.

Undercut notifier shows Last recorded sale beside Lowest competitor, using the latest matching-quality sale returned within the last 30 days. Hover for the sale timestamp. Missing sales do not suppress undercut alerts.

## Sniper buying metrics

Deals show discount versus the matching-quality sales median, recorded transactions per day, estimated purchase cost including a configurable fee, savings versus the median, and potential resale profit per item and whole stack. Profit estimates assume resale at the selected-scope median after the configured resale tax and purchase fee (both default to 5%); real prices and fees vary. Profit columns show by default and can be hidden with Show estimated resale profit. Optional minimum discount, savings and profit filters default to off and apply immediately to received deals; 1-gil alerts bypass them. Sales/day counts recorded transactions divided by the captured history window; the history entry cap can underestimate high-volume markets. Latest-sale age reflects actual recorded sale time; History checked reflects when the baseline was fetched. History baselines are not continuously refreshed during a watch session. Restart watching to refresh them. Columns are sortable and hideable, with horizontal scrolling for narrow windows. Purchases remain manual.

Existing listings has an All retainers / individual retainer dropdown and item-name search. Click headers to sort, including Retainer to group names. Last sold price uses the latest same-quality sale in loaded 30-day market data; hover for the timestamp. Saved-only rows show a dash when no sales data has been loaded. Sniper values have hover explanations and calculations, including whole-stack profit and savings on their per-item values; separate stack-profit/savings columns have been removed. Venture cycles and Sniper can run together; competing game-UI actions remain mutually exclusive. Live removed listings and updated prices that cease to qualify still remove deals, while unrelated removals no longer clear 1-gil alerts.

Sniper columns are Item | Data Center | Server | Quality | Quantity | Listing | history-window median | Discount | Sales/day | Last sale age | Est. profit/item | Savings/item. Sort Data Center or Server to group deals. Hover Quantity or Listing for whole-stack purchase cost; hover profit/item or savings/item for whole-stack totals. History-check time is on the median tooltip. All columns can be sorted and hidden, and the profit toggle remains enabled by default.

Sniper retries timed-out or temporarily failed 100-item history batches as sequential groups of 50, then 25 if necessary. New batches start at 100 again. If any items still fail, the status says Scan incomplete and Retry failed items repeats only those items while keeping the live feed and successful baselines.

Specific-item mode is highlighted orange. Sniper history days 0 uses any-age returned sales (up to 500 per item) while still requiring minimum sales; Estimated sales/day uses returned sample coverage in that mode, requiring at least two same-quality sales and a usable time span.

Undercut notifier has its own World (default), Data Center and Region (home region only) scope. Starting Sniper with the same scope also runs notifier checks every 60 seconds; stopping Sniper ends linked checks unless independent notifier watching is active. The notifier alone does not start Sniper. Server identifies the lowest matching competitor. These are separate listing requests, not Sniper sales-history estimates.

Est. sales/day uses the configured days for uncapped fixed-window scans, or the oldest returned sale-to-history-check span for capped or any-age samples. Hover for sample count and coverage.

History days 0 uses one history batch at a time with at least one second between request starts, including retry and smaller fallback requests. Fixed-window scans retain two concurrent batches. Both keep 100-item starting batches and the 50/25-item fallback.
